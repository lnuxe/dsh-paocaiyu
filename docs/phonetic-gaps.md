# 音标缺口审计

> 更新：2026-11-25 · 插件 `v0.7.2` · 数据源 `qwerty-learner/public/dicts`（371 库 / 414,469 条原始）
> 口径：**client.js 自己的归一化函数**（`__test.normalizeWord`）+ **自己的展示函数**（`__test.phoneticOf`）
> 脚本：`node scripts/audit-phonetic.mjs [--upstream <dicts>] [--top N] [--json]`
> 复现：`node scripts/audit-phonetic.mjs --top 30`

## 0. 一句话结论

**音标缺口 100% 来自数据，不来自代码。** 有字段的 289,774 条，界面一条都没漏显示；
缺音标的 124,515 条（30.06%）在上游 json 里就没有 `usphone` / `ukphone`。
真正需要改的是**展示面**：错词本与结算页的错词胶囊拿到了音标却没有渲染（见 §4）。

## 4. 「数据里就没有」 vs 「我们有字段却没显示」

这是本次审计的核心判断题，脚本用两列数字回答：

| 判据 | 结果 |
| --- | --- |
| 原始 json 里有 `usphone` / `ukphone` 的条数（`rawPhone`） | 289,774 |
| 归一化后界面能拿到的条数（`both + usOnly + ukOnly`） | 289,774 |
| **差值 = 有字段却没显示（`hidden`）** | **0 条** |

逐库核对同样为 0：371 个库里没有任何一个库出现 `rawPhone > 有音标条数`。
`lostUs` / `lostUk`（原始有那一支、归一化后为空）也都是 0 —— `buildIpa()` 没有吞掉任何一条。

**结论：数据链路没有 bug。** 缺的 124,515 条，打开上游 json 就是没有这个字段。

### 4.1 但展示面有 2 处真 bug：拿到了却不渲染

`lookup(word)` 能给每个词返回 `ipa` / `us` / `uk`，但这**两个界面没把它画出来**：

| 界面 | 代码位置 | 现状 | 影响 |
| --- | --- | --- | --- |
| 错词本每一行 | `client.js` `WrongBookPanel` | 只渲染 `单词 / 释义 / ×次数 / 已掌握` | 所有进过错词本的词 |
| 结算页错词胶囊 | `client.js` `ResultScreen` 的 `qat-mistake` | 只渲染 `单词 ×次数` + 释义 | 本轮打错的词 |

复现（这 5 个库覆盖率 93%–100%，下面每个样例词条本身都带两支音标，已逐条核对原始 json）：

| 词库 | 词条 | 数据里的音标（`usphone` / `ukphone`） | 错词本 / 结算页 |
| --- | --- | --- | --- |
| `CET4_T.json` | `abandon` | `əˈbændən` / `əˈbændən` | 不显示 |
| `CET4_T.json` | `elegant` | `ˈɛləgənt` / `ˈelɪgənt` | 不显示 |
| `Oxford5000.json` | `ability` | `əˈbɪləti` / `əˈbɪləti` | 不显示 |
| `PTE_senior.json` | 任一词（库覆盖 100%，3,141/3,141） | 有 | 不显示 |
| `TOEFL_ZhangHongYan.json` | 任一词（库覆盖 100%，4,020/4,020） | 有 | 不显示 |

复现步骤：随便打错 `abandon` → 打开错词本 → 该行没有音标；结算页的错词胶囊同样没有。
修复口径：两处都改成 `phoneticOf(lookup(row.word), settings.accent).text`，和面板/跟打条同一函数，
**不要**自己拼 `us || uk`。

### 4.2 与音标相邻、但不算「音标缺口」的两件事

1. **假名注音不逐字**（`ja` 27,139 条 + `kk` 6,004 条只有 `notation`）：上游 `Word/Notation.tsx` 用
   `<ruby><rt>` 把 `汉字(かんじ)` 逐字注音；我们只是纯文本副行（`.qat-gloss-notation`）。
   这是排版缺口，记在 `parity-scan.md` §5（N16），不在本文统计。
2. **假名词库发音走错接口**：`pronunciationSrc()` 只认 `us` / `uk` / `ja` / `zh`，
   `aiueo` 这种罗马字会被当成英文（`type=2`）。上游走 `romajiToHiragana()` 再 `le=jap`。
   记在 `parity-scan.md` §5（N17）。

## 5. 建议（按性价比）

| # | 动作 | 工作量 | 收益 |
| --- | --- | --- | --- |
| 1 | 错词本 + 结算页补音标（同一个 `phoneticOf`） | S | 立刻让 28.9 万条有音标的词在两个界面可见 |
| 2 | 面板/跟打条在无音标时**不显示空行**（已经是这个行为，加测试钉住） | S | 避免以后有人加「兜底音标」编数据 |
| 3 | 82 个 0% 英语库在词库列表打「无音标」角标，别让人以为是 bug | S | 把数据问题前置告知用户 |
| 4 | 假名 ruby 逐字注音 | S | 3.3 万条日/哈词条的读音可读性 |
| 5 | 去上游补数据（`usphone`/`ukphone`） | L | 只能上游做，本地不编造 |

> 明确不做的：**不要**用规则给 82 个 0% 库生成音标。数据里没有就写「无」，编出来的音标比没有更糟。
